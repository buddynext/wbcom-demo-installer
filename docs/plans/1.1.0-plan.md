# 1.1.0 implementation plan

Written 10 November 2026 after replicating every card on the lab (`docs/qa/replication-1.1.0.md`) and reading the
code each fix touches. Order is by what a customer feels. Every item lists the cause, the change, which entry points
it reaches (wizard, REST, WP-CLI) and the check that must fail on 1.0.0 and pass after.

Rules that shape every item: product APIs only, everything recorded in the ledger, never touch the owner's users or
content, exact plan counts, no new table or option without the owner's yes.

## Batch E: WP-CLI matches the wizard

`--format=json` on `build`, `finish`, `verify`, `resume`; non-zero exit on problems; `--install-missing`, `--name`,
`--tagline`, `--remove`; `status` lists install state. Every wizard choice has a flag.

## Batch F: AI site builder (WordPress core AI only)

One seam `src/Ai/Brief.php`: `available()` is `function_exists( 'wp_ai_client_prompt' ) && wp_supports_ai()` plus a
model for text generation; otherwise the AI option is hidden. Lab WordPress 7.1.3 has the client; with no connector it
returns "No models found that support text_generation", which is the hidden case.

1. Wizard step 1 gets "Describe your site" (one text box). REST `POST /brief` asks core for JSON against a schema:
   site name, tagline, starting point, products (from what is installed or installable), tone, niche words.
2. The brief fills the normal wizard choices (starting point, products, name, tagline); the owner sees the usual
   Review with exact counts and changes anything before Build. Nothing is written before Build.
3. Content packs (rewritten names and text per provider in the shape of `content/<id>.php`) come after the brief works,
   validated per provider; a provider whose pack fails uses our curated content.
4. CLI: `build --describe="..."`.

## Risks found while planning

1. **Pro toggles load at boot.** Learnomy Pro and Listora Pro read their feature list when they boot, so a toggle set
   in a step only takes effect on the next request. The wizard runs one step per request, so it works there; WP-CLI
   runs all steps in one process, so Pro content steps would see the feature off. Plan: CLI runs each step in its own
   process (`WP_CLI::runcommand( 'wbcom-demo step', array( 'launch' => true ) )`), which also fixes the 128 MB
   problem for long builds and matches the wizard exactly.
2. **Pro extensions need a licence** (Jetonomy Pro): a demo on a site without a licence shows Pro as "needs licence".
3. **Product gaps** that need cards on the product boards (we work around them, never edit products): WPMediaVerse
   challenge delete; BuddyNext subscription delete; Jetonomy `Post::create` not firing its create action.
