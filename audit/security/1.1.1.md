# Security gate: Wbcom Demo Installer 1.1.1

Date: 2026-11-17. Branch 1.1.1.

## G1 sweep (security-sweep.sh, 82 own-code PHP files)
No CRITICAL patterns. The two MEDIUM findings are the same as 1.1.0 (see 1.1.0.md): `Admin\Page::dismiss()` and
`Core\Guide::go()` check the capability after the nonce, and `uninstall.php` is guarded by `WP_UNINSTALL_PLUGIN`.

## G2 authorisation matrix (wbcom-demo/v1)
No new routes: 10 routes, all `permission_callback` = `Rest\Controller::can()` = `current_user_can( Plugin::CAP )`
(site administrator); 401 signed out, 403 for any other role.
- `POST /build` takes a new `demo` argument, cleaned with `sanitize_key` and used only to look up a name in the
  plugin's own `content/demos.php`.
- `POST /install` now also takes `addon:<folder>`. It only switches on an add-on that is already installed and whose
  folder a demo names (`Demos::addon_folders()`), and only for a user who may activate plugins; it never downloads.

## G3 reviewed diff (v1.1.0..1.1.1)
- Demo card images load from `https://wbcomdesigns.com/images/sandboxes/<host>.webp`, the host taken from the demo's
  own preview URL in `content/demos.php` and `rawurlencode`d; no request data reaches the URL.
- Every new value the wizard shows (demo name, purpose, image URL, page links, the front page id) is escaped with
  `esc()` or cast to an integer on the server.
- WP-CLI `install` reads the full product catalog; it installs only catalog entries, from the same trusted hosts.

Result: PASS.
