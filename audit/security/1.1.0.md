# Security gate: Wbcom Demo Installer 1.1.0

Date: 2026-11-17. Branch 1.1.0.

## G1 sweep (security-sweep.sh, 80 own-code PHP files)
No CRITICAL patterns.
- MEDIUM nonce-only-auth: `Admin\Page::dismiss()` checks `current_user_can( Plugin::CAP )` after the nonce;
  `Core\Guide::go()` (account switching on the Try the demo page) acts only for the site owner (`owner()`:
  an administrator, or an administrator's switched session; hardened in 1.1.0 to require manage_options on
  the switched-from account) and only to accounts the guide offers. Not exploitable.
- MEDIUM no-abspath-guard: `uninstall.php`, guarded by `WP_UNINSTALL_PLUGIN` (WordPress standard).

## G2 authorisation matrix (route-authority-scan.php, wbcom-demo/v1)
10 routes, all `permission_callback` = `Rest\Controller::can()` = `current_user_can( Plugin::CAP )` (site
administrator); 401 signed out, 403 for any other role. No route takes an object id from the request.
`POST /install` accepts a catalog id or an update id only from the site check's own list (Installer::update
matches it against reign_updates()), so it cannot install or update any other plugin.

## G3 reviewed diff (v1.0.0..1.1.0)
- Package downloads: wordpress.org, wbcomdesigns.com and github.com only, host-checked by `Installer::trusted()`.
- Member-written text written into page content (group names and descriptions) is escaped and its shortcode
  brackets encoded (`Core\Blocks::text()`).
- Wizard REST writes to core `/wp/v2/pages/<id>` for the designed home page run as the admin, on a page the
  ledger recorded.

Result: PASS.
